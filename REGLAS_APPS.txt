================================================================
  REGLAS PARA APPS DE VICWEBOS
  Última actualización: 2026
================================================================

Estas reglas aplican a TODAS las apps que se desarrollen o
integren en VicWebOs. Son de cumplimiento obligatorio para
mantener consistencia, portabilidad y compatibilidad con
GitHub como backend.

================================================================
  REGLA 1 — DATOS EN JSON POR APP
================================================================

Cada app guarda su información en archivos JSON ubicados
dentro de su propia carpeta en /app.

ESTRUCTURA BASE:

    app/
      {nombreHerramienta}/
        {nombreHerramienta}.json              ← datos globales
        {codigoUsuario}{nombreHerramienta}.json  ← datos por usuario

Una app puede usar:
    - UN SOLO JSON global
    - VARIOS JSON (uno por usuario)
    - AMBOS (global + por usuario)

La estructura depende de las necesidades de cada app. Lo
IMPORTANTE es respetar el patrón de nombres y la carpeta.

----------------------------------------------------------------
  PATRÓN DE NOMBRES
----------------------------------------------------------------

GLOBAL (toda la app, todos los usuarios):
    app/{nombreHerramienta}/{nombreHerramienta}.json

    Ejemplos:
        app/twevan/twevan.json
        app/calendario/calendario.json
        app/galeria/galeria.json
        app/chequera/chequera.json

POR USUARIO (un archivo por cada cuenta):
    app/{nombreHerramienta}/{codigoUsuario}{nombreHerramienta}.json

    Ejemplos (usuario 1234A):
        app/calendario/1234Acalendario.json
        app/galeria/1234Agaleria.json
        app/chequera/1234Achequera.json

    Ejemplos (usuario 5678B):
        app/calendario/5678Bcalendario.json
        app/galeria/5678Bgaleria.json
        app/chequera/5678Bchequera.json

REGLAS DEL PATRÓN:
    - codigoUsuario va PRIMERO, sin separador, seguido del
      nombre de la herramienta. Ej: 1234Agaleria.json
    - El código conserva su mayúscula (1234A), el nombre de
      la herramienta va en minúsculas.
    - El nombre de la herramienta debe coincidir con el "id"
      de la app en JsRutas.js (sin guiones bajos, tal cual).

----------------------------------------------------------------
  CUÁNDO USAR CADA UNO
----------------------------------------------------------------

GLOBAL → cuando TODOS los usuarios comparten los datos.
    Ej: twevan.json (red social entre OCs, todos ven todo)
        encuestas.json (encuestas globales)

POR USUARIO → cuando cada usuario tiene SUS propios datos.
    Ej: 1234Acalendario.json (sus eventos)
        1234Achequera.json (sus monedas)
        1234Alogros.json (sus logros)

AMBOS → cuando parte es compartida y parte es personal.
    Ej: app/quizatorio/quizatorio.json        (todos los quizzes)
        app/quizatorio/1234Aquizatorio.json   (respuestas usuario)

----------------------------------------------------------------
  ESTRUCTURA INTERNA DEL JSON
----------------------------------------------------------------

El JSON debe contener un objeto con una propiedad "datos"
(o el nombre que tenga sentido para la app) que almacene
todo el estado.

EJEMPLO DE ESTRUCTURA RECOMENDADA:

    {
        "version": 1,
        "actualizado": "2025-01-15T10:30:00Z",
        "datos": {
            // Aquí va lo que la app necesite guardar
        }
    }

REGLAS ADICIONALES:
    - Siempre escribir mediante ConfigBD.escribirArchivo().
    - Siempre leer mediante ConfigBD.leerArchivo().
    - No usar localStorage ni IndexedDB como fuente de verdad
      (solo como caché temporal si hace falta).

================================================================
  REGLA 2 — ARCHIVOS BINARIOS EN CARPETAS SEPARADAS
================================================================

REGLA GENERAL:
    PROHIBIDO guardar imágenes, videos o audios embebidos
    (base64, data-URI, blobs) dentro de los JSON.

EXCEPCIÓN ÚNICA:
    cuenta.json PUEDE contener la foto del usuario en base64
    embebida. Es el ÚNICO archivo autorizado para hacerlo.
    Razón: son fotos pequeñas (~15 KB tras redimensionar) y
    es más simple mantenerlas dentro del propio archivo de
    cuentas que crear una carpeta solo para eso.

Los archivos binarios van dentro de la carpeta de la app,
en subcarpetas por tipo:

    app/{nombreHerramienta}/{nombreHerramienta}({tipo})/{archivo}.{ext}

TIPOS DE ARCHIVO PERMITIDOS:
    - imagen
    - video
    - audio
    - documento  (pdf, docx, etc.)

EJEMPLOS:
    app/galeria/galeria(imagen)/foto_001.png
    app/galeria/galeria(imagen)/foto_002.jpg
    app/spotivic/spotivic(audio)/cancion_luna.mp3
    app/spotivic/spotivic(audio)/podcast_ep01.ogg
    app/editor_video/editor_video(video)/clip_final.mp4
    app/comics/comics(imagen)/portada_comic_01.png
    app/doxc_editor/doxc_editor(documento)/contrato.pdf

EN EL JSON DE LA APP:
    Se guarda SOLO la ruta relativa al archivo, nunca el
    contenido. Ejemplo:

    {
        "datos": {
            "fotos": [
                { "id": "foto_001", "ruta": "app/galeria/galeria(imagen)/foto_001.png" },
                { "id": "foto_002", "ruta": "app/galeria/galeria(imagen)/foto_002.jpg" }
            ]
        }
    }

REGLAS ADICIONALES:
    - Nombres de archivo sin espacios ni caracteres especiales.
      Usar guiones bajos: foto_001.png, no "foto 001.png".
    - Nombres en minúsculas siempre.
    - Extensiones en minúsculas: .png, .jpg, .mp3, .mp4
    - Un archivo = un recurso. No comprimir varios en uno.
    - Si el archivo pesa más de 25 MB, considerar dividirlo
      (límite de la API de GitHub por archivo).
    - Si un archivo se borra lógicamente, se elimina también
      del repositorio para no acumular basura.

================================================================
  REGLA 3 — ESTRUCTURA DE LAS HERRAMIENTAS
================================================================

Toda herramienta vive en su propia carpeta dentro de
/herramientas y tiene EXACTAMENTE esta estructura:

    herramientas/
      {nombreHerramienta}/
        index.html      ← HTML
        style.css       ← CSS
        script.js       ← JavaScript

REGLAS:
    - Los nombres son fijos: index.html, style.css, script.js
    - No se permiten otros nombres.
    - No se permiten subcarpetas adicionales (js/, css/, img/).
      Si una herramienta necesita assets propios, van dentro
      de la carpeta /app de esa herramienta (ver Regla 2).
    - El archivo se referencia desde JsRutas.js así:
        ruta: 'herramientas/{nombreHerramienta}/index.html'
    - El id en JsRutas.js debe coincidir con el nombre de la
      carpeta y con el nombre de los JSON en /app.

EJEMPLO — App "galeria":
    herramientas/galeria/index.html
    herramientas/galeria/style.css
    herramientas/galeria/script.js

    JsRutas.js:
        {
            id: 'galeria',
            nombre: 'Galería',
            icono: 'image',
            ruta: 'herramientas/galeria/index.html',
            descripcion: 'Tus fotos favoritas',
            categoria: 'Creación y Recuerdos'
        }

    Datos:
        app/galeria/galeria.json
        app/galeria/1234Agaleria.json
        app/galeria/galeria(imagen)/foto_001.png

================================================================
  TABLA RESUMEN
================================================================

  TIPO DE DATO       → DÓNDE VA
  ------------------------------------------------------------
  Código de app      → herramientas/{nombre}/
                         index.html
                         style.css
                         script.js

  Texto, números,    → app/{nombre}/{nombre}.json          (global)
  fechas, listas,      o
  configuración        app/{nombre}/{codigo}{nombre}.json (por usuario)

  Foto de usuario    → cuenta.json (base64)  ← ÚNICA EXCEPCIÓN

  Imágenes           → app/{nombre}/{nombre}(imagen)/archivo.png
                       (referencia en el JSON)

  Videos             → app/{nombre}/{nombre}(video)/archivo.mp4
                       (referencia en el JSON)

  Audios             → app/{nombre}/{nombre}(audio)/archivo.mp3
                       (referencia en el JSON)

  Documentos         → app/{nombre}/{nombre}(documento)/archivo.pdf
                       (referencia en el JSON)

================================================================
  API DISPONIBLE (recordatorio)
================================================================

Para leer datos:
    const data = await ConfigBD.leerArchivo(
        'app/galeria/galeria.json'
    );

Para escribir datos:
    await ConfigBD.escribirArchivo(
        'app/galeria/galeria.json', data
    );

Para leer datos de un usuario:
    const codigo = cuentaActual.codigo; // ej: "1234A"
    const data = await ConfigBD.leerArchivo(
        `app/calendario/${codigo}calendario.json`
    );

Para archivos binarios:
    - Se subirán vía la API de GitHub (contents API)
    - Se leerán con la misma API y se mostrarán con blob URLs
    - Nunca se guardan como base64 en el JSON (excepto cuenta.json)

================================================================
  POR QUÉ ESTAS REGLAS
================================================================

1. Estructura fija de herramientas (index.html, style.css,
   script.js) → cada app es autocontenida, sin ambigüedad,
   sin dependencias de rutas raras.

2. Carpeta por app en /app → todos los datos de una app
   quedan juntos, fácil de auditar, fácil de borrar, fácil
   de compartir.

3. Patrón {codigo}{herramienta}.json → predecible, sin
   ambigüedad, cada app sabe exactamente dónde buscar los
   datos de cada usuario.

4. Archivos binarios separados por tipo → los JSON se
   mantienen pequeños y legibles, no se infla el repo con
   base64, y GitHub puede manejar cada archivo individualmente.

5. Excepción única para cuenta.json → las fotos de perfil
   son pequeñas y necesitan estar en el mismo archivo que
   la cuenta para simplificar la carga inicial.
