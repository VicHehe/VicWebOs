================================================================
  VICWEBOS — DOCUMENTO MAESTRO DEL PROYECTO
  Última actualización: 2026
================================================================

Este documento describe TODA la arquitectura, reglas y estado
actual de VicWebOs. Cualquier desarrollador (humano o IA) que
retome el proyecto debe leerlo completo antes de tocar código.

================================================================
  1. FILOSOFÍA DEL PROYECTO
================================================================

VicWebOs es un "sistema operativo web" personal o grupal. No es
una app normal: es un shell con apps instalables, temas
intercambiables y widgets. Está pensado para grupos pequeños
(pareja, amigos, familia) que comparten un mismo repositorio de
datos.

Objetivos:
    - Instalable y desinstalable (apps, temas, widgets)
    - Persistente (todo se guarda)
    - Personalizable (temas, accesos, widgets)
    - Gamificado (monedas, espacio, recompensas)
    - Auto-contenido (no requiere backend)

================================================================
  2. ARQUITECTURA DE REPOSITORIOS (CRÍTICO)
================================================================

Hay DOS repositorios separados:

REPO 1 — CÓDIGO — VicWebOs/
    Contiene TODO el código fuente del OS y las apps.
    Puede ser público o privado.
    Se hostea en GitHub Pages / Vercel / Netlify / local.

REPO 2 — DATOS — vicwebos-data/
    Contiene TODOS los datos del grupo (cuentas, configs, apps).
    Debe ser PRIVADO.
    El usuario lo conecta con un token de GitHub desde el OS.

El código se actualiza una sola vez para todos. Los datos son
privados por grupo. Cada grupo puede tener su propio
vicwebos-data compartido con sus amigos.

================================================================
  4. REGLAS DE DATOS
================================================================

REGLA 1 — JSON POR APP
    Cada app guarda sus datos en vicwebos-data/app/{nombreApp}/
    Puede usar 1 JSON global, varios por usuario, o ambos.
    Patrón global:      {nombreApp}.json
    Patrón por usuario: {codigoUsuario}{nombreApp}.json
    Ejemplo usuario 1234A:
        app/calendario/calendario.json
        app/calendario/1234Acalendario.json

REGLA 2 — IMÁGENES (GALERÍA GLOBAL)
    >>> CAMBIO IMPORTANTE <<<

    Las IMÁGENES ya NO se guardan dentro de la carpeta de cada app.
    Van a una carpeta GLOBAL del usuario:

        Galeria{CODIGO}/img_xxx.jpg
        Galeria{CODIGO}/galeria.json

    Cada usuario tiene SU carpeta Galeria{CODIGO}/ con todas sus
    fotos. Esto evita duplicar la misma imagen en varias apps y
    permite reutilizarla en cualquier lado.

    Estructura del JSON por usuario (Galeria{CODIGO}/galeria.json):
        {
          "version": 1,
          "codigo": "0308V",
          "actualizado": "ISO",
          "carpetas": [
            { "id": "c_general", "nombre": "General", "creada": "ISO" }
          ],
          "imagenes": [
            {
              "id": "img_xxx",
              "nombre": "playa.jpg",
              "archivo": "img_xxx.jpg",
              "carpeta": "c_general",
              "tipo": "image/jpeg",
              "tamano": 342000,
              "subida": "ISO"
            }
          ]
        }

    JSON GLOBAL (app/galeria/galeria.json) — índice intermediario:
        {
          "version": 1,
          "actualizado": "ISO",
          "usuarios": {
            "0308V": { "carpetas": [...], "imagenes": [...] },
            "1234A": { "carpetas": [...], "imagenes": [...] }
          }
        }
    Se mantienen sincronizados en cada operación. El global es lo
    que el picker lee para mostrar rápido todas las imágenes de
    todos los usuarios.

    Las apps guardan SOLO el id de la imagen (imagenId), NO la
    ruta. Al mostrar, resuelven con MasterHad.galeria.leerImagenURL(id).

    Si el usuario borra una imagen de la Galería, deja de estar
    disponible en todas las apps automáticamente.

REGLA 3 — OTROS BINARIOS (audio, video, documento)
    Van en subcarpetas dentro de la carpeta de la app:
        app/{nombreApp}/{nombreApp}(audio)/archivo.mp3
        app/{nombreApp}/{nombreApp}(video)/archivo.mp4
        app/{nombreApp}/{nombreApp}(documento)/archivo.pdf
    En el JSON se guarda solo el nombre del archivo.
    PROHIBIDO guardar base64 en los JSON (excepción: cuenta.json
    que puede guardar la foto de perfil del usuario en base64).

REGLA 4 — ESTRUCTURA DE APPS
    herramientas/{nombreApp}/
        index.html
        style.css
        script.js
    Nombres fijos, sin subcarpetas, sin excepciones.

REGLA 5 — TEMAS
    Cada tema es UN archivo CSS:
        Temas/{nombreTema}.css
    Se carga en index.html con:
        <link rel="stylesheet" href="Temas/{nombre}.css" id="tema-activo">
    Al cambiar tema, se reemplaza el <link id="tema-activo">.
    El tema puede sobreescribir CUALQUIER regla CSS del style.css
    base: colores, layout, tipografía, sombras, todo.

REGLA 6 — WIDGETS
    Widgets/{nombreWidget}/
        index.html
        style.css
        script.js
    Igual que apps pero se renderizan en el welcome screen.

REGLA 7 — COMPATIBILIDAD CON TEMAS
    APPS: NO están obligadas. Recomendado usar var(--algo, fallback).
    WIDGETS: SÍ están obligados. Deben leer variables CSS del padre
    y escuchar mensajes 'vicwebos_tema_cambio'.
    STOR-HE: Hereda el tema (es una app pero por coherencia visual
    se comporta como widget).

================================================================
  5. SISTEMA DE CUENTAS
================================================================

Crear cuenta:
    - Nombre
    - Pronombre (el / ella / elle)
    - Código único de 4 dígitos + 1 letra mayúscula (formato: 1234A)
    - Foto opcional (se guarda en base64 en cuenta.json)

Entrar con código:
    - El código se guarda en localStorage (device-specific)

Datos por cuenta (cuentaConfig.json):
    {
        "1234A": {
            "appsInstaladas": ["stor-he", "chequera", "galeria"],
            "temasInstalados": ["violeta"],
            "temaActivo": "violeta",
            "widgetsInstalados": [],
            "widgetsActivos": [],
            "espacioMaximo": 50,
            "monedas": 0,
            "accesosRapidos": ["stor-he", "chequera", "galeria"]
        }
    }

Migración automática:
    Al iniciar sesión, migrarAppsPorDefecto() añade apps con
    esBase:true o esDefault:true que el usuario no tenga.

================================================================
  7. CHEQUERA Y ECONOMÍA
================================================================

La Chequera es una app del sistema (esBase + esDefault).
Registra TODOS los movimientos de monedas.

Ubicación de datos:
    app/chequera/{codigo}chequera.json  (uno por usuario)

Estructura:
    {
        "version": 1,
        "movimientos": [
            {
                "id": "mov_xxx",
                "tipo": "canje" | "gasto",
                "icono": "texto",
                "fuente": "nombreApp",
                "texto": "descripción",
                "cantidad": 50 (positivo) o -20 (negativo),
                "fecha": "ISO"
            }
        ]
    }

API GLOBAL:
    window.parent.__vicwebos.canjear(icono, fuente, texto, cantidad)
    window.parent.__vicwebos.gastoBoleta(icono, fuente, texto, cantidad)
    await window.parent.__vicwebos.chequeraLeer()

padre leyendo getComputedStyle(document.documentElement) y

================================================================
  14. GALERÍA Y PICKER
================================================================

La Galería es una app base (no desinstalable) que centraliza
TODAS las imágenes del usuario. Otras apps nunca suben ni
borran imágenes directamente: usan el picker.

PICKER:
    Es un modal que MasterHad inyecta en el shell como overlay.
    Carga herramientas/galeria/picker.html en un iframe. El
    picker lee del JSON global (app/galeria/galeria.json) todas
    las imágenes del usuario actual, las muestra en un grid con
    paginación de 6 por página, y devuelve los ids por
    postMessage.

    Cualquier app lo usa así:
        const id = await mh.galeria.abrirPicker({ multiple: false });
        if (id) { /* guardar id en el JSON de la app */ }

    El shell recibe los mensajes:
        { type: 'galeria:pick', ids: [...] }
        { type: 'galeria:cancel' }

    Mientras el picker está abierto, no se puede abrir otro.

================================================================
  18. CHECKLIST PARA CREAR UNA APP NUEVA
================================================================

1. Decidir el id (minúsculas, sin guiones)
2. Crear herramientas/{id}/ con index.html, style.css, script.js
3. Registrar en JsRutas.js con:
    { id, nombre, icono, ruta, descripcion, categoria,
      esBase, esDefault, espacio, monedas }
4. Decidir qué guarda:
    - Nada / Global / Por usuario / Ambos
5. ¿Usa imágenes? → NO subir. Usar mh.galeria.abrirPicker()
6. ¿Usa audio/video/doc? → mh.publicarAudio/Video/Documento()
7. ¿Usa monedas? → api.canjear() / api.gastoBoleta()
8. Compatibilidad con temas:
    - Recomendado para apps
    - OBLIGATORIO para widgets, Stor-He, picker

TEMPLATE DE HERENCIA DE TEMA:

    function aplicarTemaDelPadre() {
        try {
            const rootPadre = window.parent.document.documentElement;
            const stylePadre = getComputedStyle(rootPadre);
            const vars = [
                '--violet-50','--violet-100','--violet-200','--violet-300',
                '--violet-400','--violet-500','--violet-600','--violet-700',
                '--white','--bg','--bg-alt',
                '--gray-50','--gray-100','--gray-200','--gray-300','--gray-400',
                '--gray-500','--gray-600','--gray-700','--gray-800','--gray-900',
                '--border','--text','--text-2','--text-3',
                '--shadow-xs','--shadow-sm','--shadow-md','--shadow-lg','--shadow-xl',
                '--accent-gradient','--accent-gradient-hover',
                '--accent-shadow','--accent-shadow-hover',
                '--accent-text-gradient',
                '--r-sm','--r-md','--r-lg','--r-xl','--r-full'
            ];
            vars.forEach(v => {
                const val = stylePadre.getPropertyValue(v).trim();
                if (val) document.documentElement.style.setProperty(v, val);
            });
        } catch (e) { /* silencioso */ }
    }

    window.addEventListener('message', (e) => {
        if (e.data && e.data.type === 'vicwebos_tema_cambio') {
            aplicarTemaDelPadre();
        }
    });

    document.addEventListener('DOMContentLoaded', aplicarTemaDelPadre);
