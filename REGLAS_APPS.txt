================================================================
  VICWEBOS — DOCUMENTO MAESTRO DEL PROYECTO
  Última actualización: 2026
================================================================

Este documento describe TODA la arquitectura, reglas y estado
actual de VicWebOs. Cualquier desarrollador (humano o IA) que
retome el proyecto debe leerlo completo antes de tocar código.

================================================================
  1. FILOSOFÍA DEL PROYECTO
================================================================

VicWebOs es un "sistema operativo web" personal o grupal. No es
una app normal: es un shell con apps instalables, temas
intercambiables y widgets. Está pensado para grupos pequeños
(pareja, amigos, familia) que comparten un mismo repositorio de
datos.

Objetivos:
    - Instalable y desinstalable (apps, temas, widgets)
    - Persistente (todo se guarda)
    - Personalizable (temas, accesos, widgets)
    - Gamificado (monedas, espacio, recompensas)
    - Auto-contenido (no requiere backend)

================================================================
  2. ARQUITECTURA DE REPOSITORIOS (CRÍTICO)
================================================================

Hay DOS repositorios separados:

REPO 1 — CÓDIGO — VicWebOs/
    Contiene TODO el código fuente del OS y las apps.
    Puede ser público o privado.
    Se hostea en GitHub Pages / Vercel / Netlify / local.

REPO 2 — DATOS — vicwebos-data/
    Contiene TODOS los datos del grupo (cuentas, configs, apps).
    Debe ser PRIVADO.
    El usuario lo conecta con un token de GitHub desde el OS.

El código se actualiza una sola vez para todos. Los datos son
privados por grupo. Cada grupo puede tener su propio
vicwebos-data compartido con sus amigos.

================================================================
  4. REGLAS DE DATOS
================================================================

REGLA 1 — JSON POR APP
    Cada app guarda sus datos en vicwebos-data/app/{nombreApp}/
    Puede usar 1 JSON global, varios por usuario, o ambos.
    Patrón global:      {nombreApp}.json
    Patrón por usuario: {codigoUsuario}{nombreApp}.json
    Ejemplo usuario 1234A:
        app/calendario/calendario.json
        app/calendario/1234Acalendario.json

REGLA 2 — BINARIOS
    PROHIBIDO guardar imágenes/audio/video en base64 dentro de
    los JSON (excepción: cuenta.json que puede guardar la foto
    de perfil del usuario en base64).
    Los binarios van en subcarpetas dentro de la carpeta de la app:
        app/{nombreApp}/{nombreApp}(imagen)/archivo.png
        app/{nombreApp}/{nombreApp}(audio)/archivo.mp3
        app/{nombreApp}/{nombreApp}(video)/archivo.mp4
        app/{nombreApp}/{nombreApp}(documento)/archivo.pdf
    En el JSON se guarda solo la ruta relativa.

REGLA 3 — ESTRUCTURA DE APPS
    herramientas/{nombreApp}/
        index.html
        style.css
        script.js
    Nombres fijos, sin subcarpetas, sin excepciones.

REGLA 4 — TEMAS
    Cada tema es UN archivo CSS:
        Temas/{nombreTema}.css
    Se carga en index.html con:
        <link rel="stylesheet" href="Temas/{nombre}.css" id="tema-activo">
    Al cambiar tema, se reemplaza el <link id="tema-activo">.
    El tema puede sobreescribir CUALQUIER regla CSS del style.css
    base: colores, layout, tipografía, sombras, todo.

REGLA 5 — WIDGETS
    Widgets/{nombreWidget}/
        index.html
        style.css
        script.js
    Igual que apps pero se renderizan en el welcome screen.

REGLA 6 — COMPATIBILIDAD CON TEMAS
    APPS: NO están obligadas. Recomendado usar var(--algo, fallback).
    WIDGETS: SÍ están obligados. Deben leer variables CSS del padre
    y escuchar mensajes 'vicwebos_tema_cambio'.
    STOR-HE: Hereda el tema (es una app pero por coherencia visual
    se comporta como widget).

================================================================
  5. SISTEMA DE CUENTAS
================================================================

Crear cuenta:
    - Nombre
    - Pronombre (el / ella / elle)
    - Código único de 4 dígitos + 1 letra mayúscula (formato: 1234A)
    - Foto opcional (se guarda en base64 en cuenta.json)

Entrar con código:
    - El código se guarda en localStorage (device-specific)

Datos por cuenta (cuentaConfig.json):
    {
        "1234A": {
            "appsInstaladas": ["stor-he", "chequera"],
            "temasInstalados": ["violeta"],
            "temaActivo": "violeta",
            "widgetsInstalados": [],
            "widgetsActivos": [],
            "espacioMaximo": 50,
            "monedas": 0,
            "accesosRapidos": ["stor-he", "chequera"]
        }
    }

Migración automática:
    Al iniciar sesión, migrarAppsPorDefecto() añade apps con
    esBase:true o esDefault:true que el usuario no tenga.

  6. SISTEMA DE ESPACIO Y MONEDAS
================================================================

CONSTANTES ACTUALES (en Cuenta.js):
    ESPACIO_INICIAL        = 50
    ESPACIO_POR_COMPRA     = 12
    COSTO_COMPRA_ESPACIO   = 2500
    MONEDAS_INICIALES      = 0
    MAX_WIDGETS_ACTIVOS    = 3
    MAX_ACCESOS_RAPIDOS    = 8
    MAX_TABS               = 6 (pestañas simultáneas en JsIndex.js)
    MAX_MOVIMIENTOS_CHEQUERA = 500

COSTOS DE CATÁLOGO:
    - App: 6 de espacio, 0 monedas (por defecto)
    - Widget: 4 de espacio, varía en monedas
    - Tema: 2 de espacio, 0 monedas
    - Apps/temas base (esBase:true): 0 de todo, no desinstalables
    - Puedes poner monedas a cualquier cosa (ej: dados = 15)

COMPRA DE ESPACIO:
    Desde Stor-He, la card "Ampliar espacio" cuesta 2500 monedas
    y da +12 de espacio.

================================================================
  7. CHEQUERA Y ECONOMÍA
================================================================

La Chequera es una app del sistema (esBase + esDefault).
Registra TODOS los movimientos de monedas.

Ubicación de datos:
    app/chequera/{codigo}chequera.json  (uno por usuario)

Estructura:
    {
        "version": 1,
        "movimientos": [
            {
                "id": "mov_xxx",
                "tipo": "canje" | "gasto",
                "icono": "texto",
                "fuente": "nombreApp",
                "texto": "descripción",
                "cantidad": 50 (positivo) o -20 (negativo),
                "fecha": "ISO"
            }
        ]
    }

API GLOBAL (llamable desde cualquier app):
    // Ganar monedas (aparece en chequera como +)
    window.parent.__vicwebos.canjear(icono, fuente, texto, cantidad)

    // Gastar monedas (aparece en chequera como -)
    window.parent.__vicwebos.gastoBoleta(icono, fuente, texto, cantidad)

    // Leer movimientos
    const data = await window.parent.__vicwebos.chequeraLeer();

Ambas funciones:
    - Actualizan configCuentaActual.monedas
    - Escriben en el JSON de chequera
    - Actualizan el header en el shell
    - Notifican a la chequera abierta por postMessage
    - Lanzan error si no hay cuenta o monedas insuficientes

NOTIFICACIÓN CHEQUERA:
    Mensaje: { type: 'vicwebos_chequera_cambio' }
    La chequera lo escucha y se refresca automáticamente.

================================================================
  8. API PARA IFRAMES
================================================================

Desde cualquier app/widget (que viva en un iframe):
    const api = window.parent.__vicwebos;
    const bd  = window.parent.ConfigBD;

MÉTODOS DISPONIBLES:

    // Catálogo
    api.obtenerCatalogo()   → array de apps
    api.obtenerTemas()      → array de temas
    api.obtenerWidgets()    → array de widgets

    // Estado del usuario
    api.obtenerInstaladas()        → ids de apps instaladas
    api.obtenerTemasInstalados()   → ids de temas instalados
    api.obtenerWidgetsInstalados() → ids de widgets instalados
    api.obtenerWidgetsActivos()    → ids de widgets activos
    api.obtenerTemaActivo()        → id del tema activo
    api.obtenerAccesosRapidos()    → ids de accesos rápidos
    api.estaInstalada(id)          → bool
    api.tieneCuenta()              → bool
    api.estaConectado()            → bool
    api.obtenerCuenta()            → { nombre, codigo } o null

    // Economía
    api.obtenerEspacioMaximo()   → int
    api.obtenerEspacioUsado()    → int
    api.obtenerEspacioLibre()    → int
    api.obtenerMonedas()         → int
    api.puedeInstalar({espacio, monedas}) → { ok, motivo }
    api.comprarEspacio()         → Promise

    // Chequera
    api.chequeraLeer()           → Promise<data>
    api.canjear(icono, fuente, texto, cantidad)
    api.gastoBoleta(icono, fuente, texto, cantidad)

    // Acciones (todas devuelven Promise)
    api.instalar(id)
    api.desinstalar(id)
    api.abrirApp(id)
    api.instalarTema(id)
    api.desinstalarTema(id)
    api.aplicarTema(id)
    api.instalarWidget(id)
    api.desinstalarWidget(id)
    api.activarWidget(id)
    api.desactivarWidget(id)
    api.activarAccesoRapido(id)
    api.desactivarAccesoRapido(id)

    // Constantes
    api.ESPACIO_INICIAL
    api.ESPACIO_POR_COMPRA
    api.COSTO_COMPRA_ESPACIO
    api.MAX_WIDGETS_ACTIVOS
    api.MAX_ACCESOS_RAPIDOS

DATA (ConfigBD):
    bd.leerArchivo(path)         → Promise<data|null>
    bd.escribirArchivo(path,data) → Promise<{ok}>
    bd.estaConectado()           → bool
    bd.obtenerInfo()             → { owner, repo }

NOTA: ConfigBD trabaja SIEMPRE sobre el repo de DATOS
(vicwebos-data). Los paths son relativos a su raíz.

  9. SISTEMA DE TEMAS
================================================================

Temas base oficiales actualmente:
    - violeta (base, default) — fondo blanco, violeta clásico

    --border, --text, --text-2, --text-3

    --accent-text-gradient
    --r-sm, --r-md, --r-lg, --r-xl, --r-full

TEMAS PERSONALIZADOS: un tema nuevo es solo añadir su .css a
Temas/ y su entrada en JsTemas.js. No requiere tocar el shell.

STOR-HE + WIDGETS: heredan las variables del padre leyendo
getComputedStyle(document.documentElement) y escuchando el
mensaje 'vicwebos_tema_cambio'.

================================================================
  10. SISTEMA DE PESTAÑAS
================================================================

- Máximo MAX_TABS (actualmente 6) pestañas simultáneas.
- Cada pestaña es un <iframe> con la app cargada.
- Al abrir una app ya abierta, se activa su pestaña.
- Al cerrar una pestaña, se destruye el iframe.
- El welcome screen se muestra cuando no hay ninguna pestaña.

Al abrir herramientas desde el sidebar o el modal "Ver todas"
se activan o se crean pestañas.

================================================================
  11. STOR-HE
================================================================

Stor-He es la tienda. Es la ÚNICA forma de instalar/desinstalar
apps, temas y widgets. También permite comprar espacio.

Estructura:
    - Header con logo + recursos (espacio, monedas)
    - 3 tabs: Apps | Temas | Widgets
    - Card de ampliación de espacio (solo en Apps)
    - Cards de cada item con: icono, nombre, descripción, costos,
      acciones (Instalar / Desinstalar / Aplicar / Abrir)

Validaciones:
    - No permite instalar si falta espacio o monedas
    - Muestra el motivo en el botón deshabilitado
    - Apps con esBase:true no se pueden desinstalar
    - Temas con esBase:true no se pueden desinstalar

Compatible con temas (hereda variables CSS del padre).

================================================================
  16. LIMITACIONES CONOCIDAS / DEUDAS TÉCNICAS
================================================================

1. CONCURRENCIA DE ESCRITURA
   Si dos usuarios escriben el mismo JSON al mismo tiempo,
   el segundo puede pisar al primero. Actualmente no hay
   retry ni merge automático.
   Mitigación: usar archivos por usuario siempre que sea posible.
   Fix pendiente: añadir retry con merge en ConfigBD.

2. SUBIDA DE BINARIOS NO IMPLEMENTADA
   ConfigBD solo escribe texto (JSON). Falta un método
   subirArchivo() para subir imágenes/audio/video a GitHub.
   Pendiente para cuando una app lo necesite.

3. NOTIFICACIONES GLOBALES
   No hay sistema de toasts globales desde el shell hacia el
   usuario. Solo alert() de las apps.

4. SIN TIEMPO REAL
   No hay WebSocket. Para sincronización en vivo habría que
   hacer polling o usar un servicio externo.

5. LÍMITE DE 5000 requests/hora de GitHub
   Si una app escribe muy seguido, agota el límite.
   Recomendado: acumular cambios y guardar cada 10-30s.

================================================================
  17. CHECKLIST PARA CREAR UNA APP NUEVA
================================================================

1. Decidir el id (minúsculas, sin guiones, ej: "calculadora")
2. Crear herramientas/{id}/ con index.html, style.css, script.js
3. Registrar en JsRutas.js con:
    {
        id, nombre, icono (nombre lucide), ruta,
        descripcion, categoria, esBase, esDefault,
        espacio (int), monedas (int)
    }
4. Decidir qué guarda:
    - Nada → no necesita JSON
    - Global → app/{id}/{id}.json
    - Por usuario → app/{id}/{codigo}{id}.json
    - Ambos → ambos archivos
5. ¿Usa monedas? Usar api.gastoBoleta() / api.canjear()
6. ¿Necesita binarios? Ir a subcarpetas (regla 2)
7. Compatibilidad con temas:
    - Recomendado (no obligatorio) para apps
    - OBLIGATORIO para widgets y para Stor-He

TEMPLATE DE HERENCIA DE TEMA (copiar en cada app/widget):

    function aplicarTemaDelPadre() {
        try {
            const rootPadre = window.parent.document.documentElement;
            const stylePadre = getComputedStyle(rootPadre);
            const vars = [
                '--violet-50','--violet-100','--violet-200','--violet-300',
                '--violet-400','--violet-500','--violet-600','--violet-700',
                '--white','--bg','--bg-alt',
                '--gray-50','--gray-100','--gray-200','--gray-300','--gray-400',
                '--gray-500','--gray-600','--gray-700','--gray-800','--gray-900',
                '--border','--text','--text-2','--text-3',
                '--shadow-xs','--shadow-sm','--shadow-md','--shadow-lg','--shadow-xl',
                '--accent-gradient','--accent-gradient-hover',
                '--accent-shadow','--accent-shadow-hover',
                '--accent-text-gradient',
                '--r-sm','--r-md','--r-lg','--r-xl','--r-full'
            ];
            vars.forEach(v => {
                const val = stylePadre.getPropertyValue(v).trim();
                if (val) document.documentElement.style.setProperty(v, val);
            });
        } catch (e) { /* silencioso */ }
    }

    window.addEventListener('message', (e) => {
        if (e.data && e.data.type === 'vicwebos_tema_cambio') {
            aplicarTemaDelPadre();
        }
    });

    document.addEventListener('DOMContentLoaded', aplicarTemaDelPadre);

================================================================
  18. REGLAS DE ESTILO Y UX
================================================================

ICONOS:
    - Usar SIEMPRE iconos Lucide (https://lucide.dev/icons)
    - NO usar emojis en la UI. Causan problemas entre sistemas
      operativos (Windows 10 no renderiza algunos).
    - Excepción: emojis decorativos que ya existían en el
      proyecto (banderas de países en reloj-mundial). Evaluar
      caso a caso.

COLORES:
    - NUNCA hardcodear colores. Usar var(--algo, fallback).
    - El fallback debe ser el color por defecto del tema violeta.

LAYOUT:
    - PC: ancho máximo razonable (800-1100px), grid si aplica
    - Móvil: apilado, sin scroll horizontal
    - Overflow-y: auto cuando el contenido pueda no caber

ESPACIADO:
    - Sistema de spacing consistente (4, 8, 12, 16, 20, 24, 32)
    - Radios: usar var(--r-sm/md/lg/xl/full)

================================================================
  19. FLUJO DE INICIO DE UNA CUENTA NUEVA
================================================================

1. Abrir VicWebOs → pantalla de login/registro
2. El usuario intenta registrarse pero no hay repo conectado
   → se muestra aviso para conectar GitHub primero
3. Configurar Base de Datos → conectar con GitHub (token+repo)
4. Crear cuenta (nombre, pronombre, foto, código)
5. Se crea cuentaConfig.json con:
   - appsInstaladas: [stor-he, chequera]
   - tema: violeta
   - accesosRapidos: [stor-he, chequera]
6. Se abre el welcome screen con saludo personalizado
7. El usuario puede:
   - Abrir Stor-He para instalar más apps
   - Abrir Chequera para ver sus monedas (0 al inicio)
   - Configurar tema, widgets, accesos

================================================================
  20. API DE CHEQUERA — EJEMPLO COMPLETO
================================================================

Desde cualquier app que quiera dar monedas al usuario:

    const api = window.parent.__vicwebos;
    try {
        await api.canjear(
            'trofeo',              // icono (nombre lucide o texto)
            'mi_app',              // fuente (nombre de la app)
            'Ganaste un logro',    // texto descriptivo
            50                     // cantidad
        );
        // Al usuario se le suman 50 monedas
        // Aparece +50 en su chequera
    } catch (e) {
        console.error('No se pudo dar monedas:', e);
    }

Desde cualquier app que quiera cobrar al usuario:

    try {
        await api.gastoBoleta(
            'calc',
            'calculadora',
            'Función Intereses',
            5
        );
        // Al usuario se le restan 5 monedas
        // Aparece -5 en su chequera
    } catch (e) {
        // Si no tiene monedas suficientes, lanza error
        alert(e.message);
    }

================================================================
  21. CÓMO PROBAR LOCALMENTE
================================================================

1. Abrir VicWebOs (con iniciar.bat o servidor local)
2. Configurar Base de Datos con un repo de prueba privado
3. Crear cuenta
4. Abrir Stor-He → Instalar Calculadora
5. Ir a Chequera → ver saldo en 0
6. Abrir Calculadora → intentar comprar función
7. Fallará por falta de monedas → mensaje correcto
8. Para probar más fácil, desde consola del navegador:
   window.parent.__vicwebos.canjear('bug', 'test', 'Monedas de prueba', 100)
